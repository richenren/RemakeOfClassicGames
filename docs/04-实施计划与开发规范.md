### 阶段 2：肉鸽核心循环

- 灵气球掉落、吸收、合并与延迟吸附。
- 升级三选一、暂停战斗/计时、六个自动攻击技能、Lv3 分支。
- 被动法器、主动道术、通用强化与两条首版技能进化。
- 加入角色选择与两个角色的专属被动，继续共用同一套技能、升级和槽位系统。
- 两次净化法坛、受控精英、尸潮阶段生成。

验收：技能/法器槽位规则正确；随机池合法；两个角色的被动差异有效且不会绕过精英/Boss 控制抗性；升级和法坛选卡时战斗完全暂停；法坛未完成死亡不发奖，已完成法坛的功德/长期任务奖励可在本局失败后保留，局内临时强化不跨局。

### 阶段 3：尸王 Boss 与完整单局

- 实现尸王三种核心招式、50% 转阶段、半随机状态机与短暂恢复窗口。
- 实现大障碍撞停冲锋、Boss 区域边界、第二法坛可达约束。
- 实现软时间压力、Boss 击杀收尾、胜负结算与再来一局。

验收：标准难度下存在可行通关路线；普通小怪不显示范围预警、Boss 关键招式预警清楚；Boss 死亡后进入胜利结算，失败按统一规则结算。

### 阶段 4：本地多存档与恢复

- SaveManager、版本化 schema、原子写与历史回退。
- 多存档槽独立功德/境界/解锁/配置/试炼/局内快照。
- 本地约每 5 秒保存，关键事件立即保存。
- 重置当前局与重置整个存档严格区分。

验收：重开当前局保留长期成长；重置一个存档不影响其他槽；异常退出后可从最后有效快照恢复。

## V0.2：NAS 同步与冲突保护

- FastAPI + SQLite 服务端和容器部署清单。
- 约每 15–30 秒异步同步，关键事件触发同步尝试。
- 版本校验、单写者保护、冲突提示、历史备份、离线重试。
- 明确区分本地保存成功与 NAS 同步成功。

验收：NAS 离线不影响游玩；多设备冲突不静默覆盖；可恢复历史版本。

## 阶段 5：美术、手感与性能打磨

- 根据可玩原型确认艺术风格与正式素材规格。
- 调整动画、特效、音效、UI、安全区与触控热区。

验收：Windows 与目标 Android 设备可完整游玩；性能、发热、内存和长时间运行表现达到项目可接受标准。

## 单任务 AI Coding 流程

1. 任务必须包含背景、输入输出、边界、验收标准。
2. AI 先阅读 README 与相关 docs，提出最小可实现改动。
3. 实施改动，避免未经讨论引入新框架、服务和收费依赖。
4. 运行 Godot 头less 导入/解析与必要测试；手动通过实际画面验收关键交互。
5. 必须保留日志、失败用例与未解决问题，不允许虚报成功。
6. 每次小功能完成后提交清晰 Git commit。
7. 修改存档 schema/API 时同步更新设计文档、迁移测试。
8. 游戏逻辑和角色素材按目录管理；密钥、签名、.env、私人数据等严格忽略。

## 不做事项

- V0.1 不实现在线多人、召唤流、复杂装备掉落、全技能进化树或完整属性词条系统。
- 不因未来扩展可能而提前引入微服务、Redis、消息队列或复杂 ECS。
- 不使用未经授权的经典游戏原版素材。
