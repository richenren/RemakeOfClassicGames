# 实施计划与 AI Coding 开发规范

## 阶段 0：技术基线（当前）

- [x] 确定第一款为 2D 幸存者式 Roguelite。
- [x] 优先 Windows、Android；预留 iOS。
- [x] 选用 Godot 4 + GDScript 和免费优先工具链。
- [x] 确定 NAS 云存档方向及离线优先原则。
- [ ] 确认具体游戏主题/机制/首版范围（**等待后续讨论**）。
- [ ] 确认目标测试手机、Godot 具体稳定版本及 Android SDK。
- [ ] 核实 NAS DSM、容器支持、网络接入方式。

## 阶段 1：可操作原型（游戏内容确认后）

- Godot 工程与输入抽象（键盘/触屏）。
- 临时色块玩家、测试场地、简单敌人、基础伤害。
- 自动攻击与 Game State（开始/暂停/死亡）。
- Windows 和 Android 构建验证。

**验收**：两端均可移动、受伤、击敌，无资源丢失或脚本错误。

## 阶段 2：肉鸽核心循环

- 经验/升级、随机强化、武器行为组合。
- 可控怪物生成与难度时间曲线。
- 完整一局：胜利/失败/结算（规则待确认）。

**验收**：能从启动玩到结算，升级选择生效，能重新开始。

## 阶段 3：本地存档与 NAS

- SaveManager 存档 schema、版本化迁移、原子写与回退。
- 本地定时快照及恢复。
- FastAPI + SQLite API、Docker 部署清单。
- SyncManager 离线队列、认证、幂等、乐观锁及冲突提示。

**验收**：断网仍能玩；PC 与 Android 各自可保存与加载，同步冲突不会静默丢进度。

## 阶段 4：体验、美术与发布

- 统一风格的原创/合规素材，画面与音效。
- 触控与手柄调优、无障碍基础设置。
- 性能 Profiling、不同机型测试、崩溃与恢复测试。
- Windows 可执行构建和 Android APK；iOS 后续验证。

**验收**：目标设备上完整游玩，长时间内存与帧率可接受，离线/在线体验明确。

## 单任务开发流程

1. 任务必须包含背景、输入输出、边界、验收标准。
2. AI 先阅读 README 与相关 docs，提出最小可实现改动。
3. 实施改动，避免未经讨论引入新框架、服务和收费依赖。
4. 运行 Godot 头less 导入/解析与必要测试；手动通过实际画面验收关键交互。
5. 必须保留日志、失败用例与未解决问题，不允许虚报成功。
6. 每次小功能完成后提交清晰 Git commit。
7. 修改存档 schema/API 时同步更新设计文档、迁移测试。
8. 游戏逻辑和角色素材按目录管理；密钥、签名、.env、私人数据等严格忽略。

## 测试重点

| 类别 | 验收内容 |
| --- | --- |
| 基础逻辑 | 攻击冷却、生命值、伤害、经验及随机规则 |
| 场景加载 | .tscn/.tres 引用完整、脚本解析正常 |
| PC 输入 | 键盘及可选 USB 摇杆 |
| Android | 触摸摇杆、权限、适配与后台恢复 |
| 性能 | FPS、帧耗时、内存、敌人数随时间变化 |
| 存档 | 版本升级、异常终止、部分写入、离线恢复 |
| 云同步 | NAS 掉线、认证失败、冲突 409、重复提交 |

## 不做事项

在游戏设定未确认之前，不自行增加机甲职业、装备系统、商城、关卡地图、账号注册或复杂网络玩法。当前仅输出技术与工具文档，不启动游戏代码实现。
