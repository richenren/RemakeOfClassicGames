## 2. 已确认的核心决策

- 类型：2D 俯视角幸存者式 Roguelite；道士与僵尸题材；自由混合构筑。
- 平台：Windows + Android；离线可玩；Godot 4 + GDScript。
- 单局：目标 10–12 分钟，尸王约第 8 分钟登场；击败尸王胜利，死亡失败；Boss 战无硬性超时判负。
- 操作：移动走位、自动索敌攻击、一个主动道术按钮、一个独立治疗按钮；无闪避/冲刺。
- 构筑：4 个自动攻击技能槽、1 个主动道术、3 个被动法器槽；技能 Lv1–Lv5，Lv3 一次二选一分支。
- 元素：金木水火土雷六大基础属性；冰为水系进化；首版只做水雷导电、火水蒸汽两种反应。
- 首版进化：水阵 + 寒魄法器 → 冰魄阵；雷符 + 天雷法印 → 五雷敕令。
- 敌人：行尸、跳僵、铁甲尸、尸王；精英由现有怪物变体构成，生成受控并带一个随机强化词条。
- 角色：首版两个角色——默认均衡型年轻镇邪道士、首个可解锁的控制型老派镇尸道长；共享技能系统，各有一个专属被动，不做独立技能树。
- 事件：每局两次固定法坛，分阶段解锁；第二次更难、奖励更高；尸王登场后仍可继续第二法坛。
- 局外成长：功德主要用于解锁，境界靠条件与试炼；V0.1 实现入道、凝炁。
- 存档：每个存档完全独立；本地每约 5 秒保存，NAS 每约 15–30 秒同步；离线优先、版本校验、冲突保护、历史备份；同一存档原则上不允许多设备同时写入。
- 版本范围：V0.1 为 Windows/Android 战斗与本地多存档；V0.2 加入 NAS 同步与冲突保护。

## 3. 审核时明确的规则优先级

以下规则在整理时已消除可能的误读：
1. 法坛进度：离开范围后暂停增长并缓慢衰减；回到范围继续。它覆盖早期讨论中的“离开只暂停”说法。
2. 普通怪与 Boss 预警：普通小怪不显示独立范围预警；尸王关键技能必须有明确地面预警。
3. 奖励随机：普通升级采用构筑相关加权与防挫败；法坛稀有三选一独立随机，不针对当前构筑加权。
4. 血量显示：所有怪物常驻血条；普通怪与精英不显示 HP 数字，精英额外显示词条，Boss 顶部显示血量百分比。
5. 治疗：靠近自动拾取；库存最多 2 次；满血不可使用；每次恢复最大生命值 30%；库存满时掉落留地面；过期前提示，不提供地图/边缘定位。
6. Boss 战：第二法坛在 Boss 战区内可达；Boss 被击败后立即进入收尾与结算，不继续完成法坛。

## 4. 仍待实现阶段定值或验证的内容

这些不是继续讨论核心方向的前置条件，应先做成可配置项，再用试玩数据调整：

- 各技能每级的精确伤害、范围、频率、持续时间和冷却。
- 各敌人生命、移速、接触伤害、碰撞半径与生成配额。
- 升级候选权重、经验曲线、进化机会的具体呈现方式。
- 法坛具体解锁时刻、净化进度衰减速度、固定奖励与稀有奖励池构成。
- 治疗道具存在时长、治疗来源概率、玩家受击无敌时长。
- 尸王技能冷却、预警时长、恢复窗口、二阶段节奏和软时间压力曲线。
- 80–100 同时存活普通敌人的目标在不同 Android 设备上的实际可达性。
- HUD 的最终尺寸、字体、图标、美术风格、地图艺术方向和音效；屏幕横竖方向尚需原型验证。
- 两个角色专属被动的具体数值、老派道长的解锁条件与成本，需在可玩原型阶段平衡。

## 5. 决策记录原则

- 不再为能从已确认规则直接推导的细节单独发起确认。
- 新决策只有在影响玩法体验、架构、范围、成本或兼容性时才单独确认。
- 新决定与旧决定冲突时，以用户最新明确选择为准，并同步修改对应 Spec 与本索引。
- 未定数值标记为可配置参数，不把建议值写成已经确认的硬性规则。
