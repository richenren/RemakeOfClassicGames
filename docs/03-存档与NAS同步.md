# 本地存档与 NAS 同步设计

## 1. 决策

**离线优先 + 定时快照 + 关键节点保存 + NAS 异步云同步**。不是联网实时对战，不需要 WebSocket、Redis、Kafka 或持续上传帧状态。

计划频率（可配置，先作为推荐默认值）：

- 本地：每 **10 秒**生成可恢复快照；升级完成、进入/完成关卡、暂停退出等关键事件立即保存。
- NAS：在线时约每 **30 秒**同步最新完整快照；关键事件尝试立即同步，但不能阻塞战斗。
- 手机后台杀进程可能不触发退出钩子，因此不能只靠退出保存；省电/生命周期限制应实际测试。
- 发生磁盘写入失败要反馈，不能把“本地存档成功”误认为“NAS 同步成功”。

## 2. 存档内容分层

**账号/档案（持久）**：解锁内容、已通关关卡、永久成长、成就、总游戏时长等。具体字段待玩法确认。

**局内快照**：当前关卡、时间、随机种子及生成器状态（如确有必要）、角色位置、血量、经验、等级、所持武器/升级等级、关卡波次。怪物/子弹可不保存全部实体，恢复时按确定规则重建，并赋予短暂无敌保护，属于“可继续玩”而非“逐帧还原”。

**设备本地设置**：音量、分辨率、触屏控件布局；通常不跨设备同步。

## 3. 数据示意（仅约定结构，不固定玩法）

```json
{
  "schema_version": 1,
  "slot_id": "profile_default",
  "revision": 12,
  "saved_at": "2026-10-21T09:00:00Z",
  "progress": {
    "unlocked_stage_ids": [],
    "persistent_flags": {}
  },
  "run_snapshot": {
    "stage_id": null,
    "elapsed_seconds": 0,
    "player_state": {},
    "loadout": []
  }
}
```

说明：revision 由服务端维护，客户端上传 base_revision；客户端时间仅用于显示，不可作为冲突优先级；`schema_version` 支持未来迁移。以上字段仅是技术示例，不代表游戏内容已经确认。

## 4. 同步时序

1. 启动：加载并校验本地快照；若联网且已授权，查询 NAS 远端版本。
2. 当版本一致可继续；存在不同分支时提示玩家选择，**不能静默覆盖**。
3. 玩游戏：本地安全写入；SyncManager 将最新完整快照放入待发送队列（同一存档可以合并旧的待发送任务）。
4. 上传：携带 `base_revision` + 客户端唯一请求 ID（幂等键），HTTPS + 认证令牌；服务端使用数据库事务校验版本并递增 revision。
5. 失败：保留本地快照并指数退避重试；HTTP 409 冲突则重新获取远端，进入冲突解决流程。
6. 跨设备切换：新设备拉取最后成功提交的云快照。如果上一设备未成功上传，不能承诺零进度损失。

不自动对金币、可消费资源取最大值；避免双端重复获得奖励。

## 5. API 草案

| 方法/路径 | 用途 |
| --- | --- |
| POST /api/auth/login | 家庭玩家身份验证或设备配对（细节待确认） |
| GET /api/saves/{slot_id} | 获取本用户有权限访问的快照 |
| PUT /api/saves/{slot_id} | 带 base_revision 和请求 ID 的条件更新 |
| GET /api/saves/{slot_id}/history | 获取有限历史版本，用于手动恢复 |
| GET /health | 内部健康检查，不包含私密数据 |

建议响应分别返回 updated revision、server timestamp、checksum。API 不信任客户端传入的 player_id 即授权身份。

## 6. 服务端技术与部署

- **FastAPI + SQLite**：家庭少量玩家的 CRUD 足够；SQLite 文件放 NAS 持久化目录，不放临时容器层。
- NAS：群晖 16GB 内存预期足够；部署前确认具体机型、DSM 和 Container Manager 支持。
- 接入：个人设备优先使用已建立的 ZeroTier 私有网络，配置受信任 HTTPS/TLS；若日后供非 ZeroTier 手机使用，需要有身份认证、TLS 和受控公网入口。
- 安全：令牌安全保管、速率限制、参数校验、最小权限；不将数据库端口、NAS 管理端口或无鉴权 API 直接开放公网。
- 备份：定期将 SQLite 一致性备份到另一介质/位置；RAID 不是备份。保留有限历史快照。
- 数据迁移：按 `schema_version` 管理，升级前备份，客户端可识别不兼容的快照并提示。

## 7. 一致性与恢复验收

- 离线玩 10 分钟再联网：可同步最近有效快照。
- NAS 不在线：游戏继续，本地存档有效，UI 显示未同步。
- Windows/Android 同时修改同一档案：陈旧版本上传返回 409，不丢失任一端未同步快照。
- 突然断电/进程被系统终止：可从最后成功的本地快照恢复。
- 恢复游戏时不能因重建的敌人立即造成不可避免的伤害。
- 重复请求 ID 不重复应用进度变更。
- 数据损坏可从上一份有效快照或 NAS 历史恢复。

## 8. 暂待业务确认

玩家档案创建方式、是否为孩子提供单独档案、关卡与单局关系、局外货币、云端冲突提示交互、是否允许同一档案双设备同时游玩，都在玩法确认后细化。
